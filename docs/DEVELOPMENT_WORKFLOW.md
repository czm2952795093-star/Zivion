# 开发与同步约定

2026-10-28，项目所有者明确要求：所有最新进展主动更新到本仓库，之后无需逐轮提醒。此约定适用于本项目后续开发。

每轮有实质进展时，同步对应源码、REA 研究证据、验证结果和开发日志，说明已完成内容、尚未验证的部分及后续工作。未完成或验证未通过的代码保存到开发分支，并准确标注状态；`main` 保持已验证代码。

每次交付通过验证的新版本时，同步版本说明，并在 GitHub Releases 发布对应安装包、源码包和 SHA256 校验文件。只有文档或研究变化时，无需重新发布同一安装包或增加应用版本号。

推送后核对远端提交；发布后核对附件。同步失败时保留本地成果，在交付说明中指出尚未同步的内容和原因，后续恢复时补齐。不得将本地完成等同于远端已同步。

仓库继续排除凭据、签名私钥、用户私人记录、原版 APK 及 SDK 等本地运行依赖；保留必要的第三方许可和可公开的项目验证材料。

## 提交归属检查（2026-10-29补充）

发现此前沿用的本机提交邮箱未被GitHub关联到项目所有者账号，导致已推送的提交没有归入其主页贡献。本仓库后续使用与账号ID和登录名对应的GitHub隐私邮箱；只修改本仓库配置，不改其他项目的全局配置。

同步时除核对远端提交外，还要核对GitHub返回的提交作者账号为项目所有者。历史提交保留原有日期、哈希及标签；绑定历史提交邮箱后GitHub可重新归属，无需重写历史。私有仓库的贡献展示由账号主页的Private contributions设置控制，推送成功不等于贡献格立即刷新。
